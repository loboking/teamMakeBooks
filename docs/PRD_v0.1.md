> **상태**: PoC 1차 초안 — 2026-05-02
> **작성자**: loboking
> **목표 단계**: PoC (현대 판타지 게임 소설 1편 자동 생성)

---

## 1. 비전

**"AI가 만든 웹소설" 플랫폼.** 숨기지 않는다. AI 작가들이 장르별로 페르소나를 가지고 연재하며, AI 검수팀이 방향성·캐릭터 일관성·완성도를 검증하고, AI 발행팀이 제목/태그/요약을 만들어 게시한다. 사람은 평상시 비개입, 이상 감지 시만 개입한다.

장기 목표: 다장르 / 다작가 / 장기 연재(1,000화+) 가능한 자동화 웹소설 플랫폼.

PoC 목표: 1개 장르 · 1명 작가 · 1화 자동 생성/검수/발행이 끝까지 돌아간다.

## 2. PoC 스코프 (v0.1)

| 항목 | 결정 |
|---|---|
| 장르 | 현대 판타지 게임 소설 (헌터물 / 시스템물 계열) |
| AI 작가 | 1명 (페르소나 1개) |
| 검수팀 | 3종 검수자 — ①방향성 ②캐릭터 일관성 ③소설 완성도 |
| 발행팀 | 제목 / 태그 / 한줄요약 생성 + 회차 게시 |
| 분량 | 1화 (5,000자 내외, 한국 웹소설 표준) |
| 플랫폼 | 웹 (반응형). 모바일 앱은 v1 이후 |
| 모델 | PoC: 가능한 로컬 모델 → 검증 후 **Gemini API**로 전환 |
| 메모리 | 로컬 파일 (요약집·세계관·캐릭터·회차메모) |
| 데이터 | 로컬 저장 (DB 도입은 v1 이후) |
| 수익 모델 | PoC: 무료. v1 이후 유료구독/광고/편당결제 |
| 사람 개입 | 이상 감지 시만 (텔레그램 알림 — 추후 설정) |

### PoC가 **하지 않는** 것 (Out of Scope)

- 다장르 / 다작가 동시 운영
- 장기 연재 (2화 이상)
- 모바일 앱
- 회원가입 / 결제 / 댓글 / 추천
- 표절 DB 비교 (검수 4번 항목은 v1)
- 사용자 신고 채널 (UI 자리만)
- 운영 어드민 UI (파일 직접 편집으로 충분)

## 3. 시스템 구성 — "3개의 AI 팀"

```
┌─────────────────────────────────────────────────────────┐
│              사람(loboking) — 가끔 개입                  │
│  ↑                                                       │
│  텔레그램 알림 (재시도 3회 실패 시)                       │
└─────────────────────────────────────────────────────────┘
                         ▲
                         │
      ┌──────────────────┴──────────────────┐
      │                                      │
┌──────────────┐   ┌──────────────┐   ┌──────────────┐
│  AI 작가팀    │ → │  AI 검수팀    │ → │  AI 발행팀    │
│  (Writer)    │   │  (Reviewer)  │   │ (Publisher)  │
├──────────────┤   ├──────────────┤   ├──────────────┤
│ 페르소나 기반│   │ 3종 검수      │   │ 제목/태그/요약│
│ 회차 본문 작성│   │ 통과/반려/수정│   │ 게시          │
└──────────────┘   └──────────────┘   └──────────────┘
                         ▲
                         │ 반려 → 작가에게 수정 요청
                         │ (max 3회, 실패 시 알림)
                         └──────
```

### 3.1 AI 작가팀 (Writer)

- **역할**: 페르소나·세계관·플롯 개요·이전 회차 요약을 입력받아 새 회차 본문 생성
- **PoC 페르소나**: 1명 (현대 판타지 게임 소설 전담)
- **입력**: `world_bible.md` + `characters.md` + `plot_outline.md` + `직전 N회 요약` + `이번 회차 지시`
- **출력**: `chapters/chXXX.md` (본문) + `chXXX_summary.md` (자동 요약)

### 3.2 AI 검수팀 (Reviewer) — 3종

| # | 검수자 | 검증 항목 |
|---|---|---|
| ① | **방향성 검수** | 작품 전체 방향(plot_outline.md)에서 벗어나지 않았는가 |
| ② | **캐릭터 일관성 검수** | characters.md와 직전 회차 대비 인물 성격/말투/관계가 일관적인가 |
| ③ | **완성도 검수** | 웹소설로서 읽힐 수준인가 (문장력, 흐름, 클리셰 처리, 흡입력) |

- **결과**: 통과 / 반려(이유 명시 + 수정 가이드)
- **반려 시**: 작가가 수정 가이드를 받아 재작성
- **재시도 정책**: max 3회 → 실패 시 텔레그램 알림 + 큐에 보류

### 3.3 AI 발행팀 (Publisher)

- **역할**: 검수 통과한 회차에 대해 제목 / 태그(3~5개) / 한줄요약 생성, `meta.json` 업데이트, 웹에 게시
- **추가**: 회차 시작부에 "🤖 AI 생성 콘텐츠" 배지 자동 삽입

## 4. 데이터 / 메모리 구조 (로컬 파일)

```
novels/
└── modern_fantasy_game_01/             ← 작품 1개 = 폴더 1개
    ├── meta.json                       ← 작품 메타 (작가ID, 장르, 발행상태, 회차수)
    ├── world_bible.md                  ← 세계관 (시스템 규칙, 헌터 등급, 던전 등)
    ├── characters.md                   ← 등장인물 (이름/성격/말투/관계/현재상태)
    ├── plot_outline.md                 ← 전체 줄거리 개요
    ├── chapters/
    │   ├── ch001.md                    ← 1화 본문 (Markdown)
    │   ├── ch001_summary.md            ← 1화 자동 요약
    │   └── ch001_meta.json             ← 제목/태그/요약/발행시각
    └── memory/
        ├── unresolved_threads.md       ← 미해결 떡밥
        └── continuity_log.md           ← 일관성 이슈 로그
```

```
authors/                                ← 작가 페르소나 정의 (확장형)
└── modern_fantasy_writer_01.yaml
    ├── name: "필명"
    ├── genre: modern_fantasy_game
    ├── style: "1인칭/3인칭, 문체 특성"
    ├── tone: "남성향/여성향/유머/시니컬"
    ├── favorite_tropes: [...]
    ├── avoid: [...]
    ├── sample_passages: [...]          ← few-shot 예시
    └── model: "gemini-2.5-pro"         ← 작가별 모델 다르게 가능
```

**작가 추가 = YAML 1개 추가** (코드 변경 없음).

## 5. 워크플로우 (1화 생성 시퀀스)

```
1. 사람: 작품 폴더 생성 + world_bible.md / characters.md / plot_outline.md 초기 작성
        (또는 AI 기획팀이 자동 생성 — v1 후속)
2. 작가: 컨텍스트 로드 → 1화 초안 생성 → ch001.md 저장
3. 검수①(방향성): 통과? → ② / 반려? → 수정 가이드 → 작가 재시도
4. 검수②(캐릭터): 통과? → ③ / 반려? → 수정 가이드 → 작가 재시도
5. 검수③(완성도): 통과? → 발행팀 / 반려? → 수정 가이드 → 작가 재시도
6. 발행팀: 제목/태그/요약 생성 → ch001_meta.json + AI 배지 → 웹 게시
7. 작가: ch001_summary.md 자동 생성 (다음 회차 컨텍스트용)

※ 각 검수 단계 max 3회 재시도. 실패 시 → 텔레그램 알림 + 큐 보류
※ 사람: 게시 결과만 확인. 이상 시 직접 파일 수정 가능.
```

## 7. 비기능 요구사항

### 7.1 모델 추상화

- **요구**: 로컬 모델 ↔ Gemini API 교체 시 작가/검수/발행 코드 수정 없이 설정만 변경
- **설계**: `model_provider` 인터페이스 (input → output 단일 함수). 구현체: `LocalModelProvider`, `GeminiProvider`, (추후) `ClaudeProvider`
- **전환 시점**: PoC 1화가 안정적으로 돌면 Gemini로 전환

### 7.2 알림

- **PoC**: 콘솔 로그 + `logs/alerts.log` 파일
- **추후**: 텔레그램 봇 (재시도 3회 실패, 발행 완료, 일일 리포트)

### 7.3 관측성

- 모든 모델 호출 로그 (입력/출력/토큰/소요시간) → `logs/calls/`
- 회차별 검수 이력 (몇 번 반려·재시도) → `logs/reviews/`

### 7.4 보안

- API 키는 `.env` (gitignore)
- 사용자 입력 없는 PoC라 입력 검증 부담 적음

## 9. 성공 기준 (PoC 통과 조건)

PoC는 **다음 4개를 모두 만족하면 통과**:

1. ✅ 작가팀이 5,000자 내외 1화 본문을 자동 생성 (사람 개입 0회)
2. ✅ 검수팀 3종이 모두 통과 (max 3회 재시도 내)
3. ✅ 발행팀이 제목/태그/요약 생성 + AI 배지 포함하여 웹에 게시
4. ✅ 결과 본문이 **사람이 읽었을 때 "웹소설로 읽을 만함"** (loboking 평가)

4번이 핵심 게이트. 1~3은 자동화 검증, 4는 품질 검증.

## 11. 미정 / 추후 결정 항목

- **Gemini 모델 종류**: gemini-2.5-pro vs flash (비용/품질 트레이드오프) — 작가팀 전환 시점에 결정
- **작가팀 (gemma4:e2b) 5,000자 본문 생성 능력**: 별도 검증 필요 — 기획팀 통과만으로 작가팀 통과 보장 안 됨
- **텔레그램 봇 설정**: 토큰/채팅ID (PoC 후반)
- **첫 작품의 세계관/플롯 개요**: PoC 시작 전 사람이 작성 (또는 AI 기획팀 별도 도입)
- **회차 컨텍스트 윈도우**: 직전 몇 회차 요약을 넣을지 (PoC 1화에선 불필요, 2화부터 결정)
